# handoff

対象は今のスレッド（`_ops/threads/<thread-id>/`）。今のスレッドが分からなければ、`grep -H '"type":"meta"' _ops/threads/*/*-STATE.jsonl` の一覧を見せて尋ねる（推測で書かない）。ゴールは**他のセッションが履歴を読まずに状況を把握して、作業を始められる状態**にすること。

## 1. sync を行う

sync スキルの手順（STATE.jsonl の現状反映・ログ・HUMAN.md）を、まだ済ませていなければ行う。

## 2. 次のセッションが何をするかを決める

- 今の task が途中なら、どこまで進んで何が残っているかを `detail` に書く。
- 終わったなら、`later` から次にやるものを選んで `status` を `next` にする。
- 何を・どこを・どう直すか・どう確かめるかまで書く。`detail`（2文・150字）に収まらなければ `_ops/threads/<thread-id>/work/<目的>/` にメモを作り、`refs` で指す。

## 3. note を刈り取る

STATE.jsonl の note を1つずつ見て、処置案を付ける:

- `until` の条件が満たされた → **削除**
- `promote` がある → 移行先（CLAUDE.md / docs / RULES.md）に書く内容を決めて、**移行**してから行を消す
- 引き続き必要 → **残す**
- `until` も `promote` も無い → 分類を人間に尋ねる

処置案は番号を振って人間に見せ、**承認された分だけ実行する**。承認が得られないものは、そのまま残す（勝手に消さない・移さない）。CLAUDE.md・docs・RULES.md への書き込みも承認後だけ。

## 4. STATE.jsonl を点検する

- 完了したこと・経緯が残っていたら消す。100行未満にする。
- note が5件を超える・100字を超えるものがあれば、指摘して整理する。
- `meta` が変わっていれば直す（スレッドの目的が変わったら `title` も）。

## 5. RULES.md への昇格を提案する

他のスレッドでも起きそうな知見があれば、RULES.md への追記を**ユーザーに提案する**（書くのはユーザーの指示があってから。internal-review スキル）。

## 6. 報告

何を引き継いだかを2〜3行でユーザーに伝える。話題が変わるなら、新しいセッション（または新しいスレッド）に切り替えるよう勧める。
